# Success Criteria v2

## Критерии успеха

- пользователь проходит core demo sequence через браузер;
- партия `112` одним выпуском создаёт три operation-scoped комплекта `112 + 112 + 26 = 250`;
- каждая из `250` карточек имеет уникальный внутренний UUID и `batchQuantitySnapshot = 112`, но не имеет `sequenceNumber` или номера детали;
- нормы комплектов могут различаться и не хранятся как один норматив партии;
- first-article карточка проходит positive-only gate до серийной работы комплекта;
- итог назначения полного комплекта проверяем как `60 + 52 = 112` без индивидуальной нумерации деталей;
- lifecycle-команды выполнения доступны мастеру и отклоняются для `WORKER`;
- UX и требования различают `FirstPieceAcceptance`, подтверждённую `FinalBatchAcceptance` всей партии и синтетическое per-card закрытие WorkCard;
- запрещённые действия недоступны в UI и отклоняются API;
- audit log позволяет восстановить хронологию карточки и массовой операции;
- повторный mock payroll export не создаёт вторую запись;
- проект разворачивается с чистого окружения по README, критические правила подтверждены тестами, а demo не требует ручной правки данных.

## Критерии готовности MVP

- все обязательные функции из [[mvp-scope]] реализованы;
- нет открытых критических дефектов;
- CI проходит;
- staging и production отвечают health check;
- документация соответствует реализации и [[decision-provenance]];
- интерактивный UX-прототип и demo script воспроизводимы;
- ограничения и синтетическая природа case study указаны явно;
- выполнен финальный аудит из [[project-plan]], включая структурную и семантическую проверки.

## Не является критерием успеха

- идентификация отдельных физических деталей;
- полный прогон всех `250` карточек в демонстрации;
- сходство с полноценной MES;
- количество функций вне scope, AI или максимально сложный технологический стек.
