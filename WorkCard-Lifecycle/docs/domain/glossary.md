# Glossary

Канонический словарь MVP v1. Термины различают подтверждённый AS-IS и синтетическую цифровую модель согласно [[decision-provenance]].

## Технологическая подготовка и партия

| Термин | Каноническое определение |
|---|---|
| **Production Passport / производственный паспорт** | Подготовленное синтетическое описание изделия и состава операций/групп. В исходном процессе ответственность относится к технологу; в MVP паспорт является read-only seed-данными. |
| **Operation Scope / область операции** | Одна операция или явно заданная группа операций, для которой выпускается `WorkCardSet` и задаётся норматив. |
| **Norm Hours / нормо-часы** | Норматив operation scope, используемый в карточке и mock payroll. Это не фактически отработанное время и не денежная сумма. |
| **Production Batch / производственная партия** | Синтетическое задание на выпуск заданного количества по выбранному паспорту. Партия не хранит один норматив и может иметь несколько комплектов карточек. |
| **Batch Quantity / количество партии** | Положительное целое число, например `112`. Оно копируется в карточку как контекст, но не обязано равняться общему числу карточек всех комплектов. |

## Карточки работы

| Термин | Каноническое определение |
|---|---|
| **Release / выпуск карточек** | Однократная атомарная команда, создающая все `WorkCardSet` и `WorkCard`, предусмотренные снимком паспорта партии. |
| **WorkCardSet / комплект карточек** | Комплект одной операции или группы операций. Хранит `plannedCardCount`, operation scope, норму и first-article gate. Одна партия имеет один или несколько комплектов. |
| **WorkCard / рабочая карточка** | Цифровая единица учёта нормированной работы с внутренним UUID. Не имеет порядкового номера экземпляра и не идентифицирует физическую деталь. |
| **Batch Quantity Snapshot** | Неизменяемая копия количества партии в карточке. Значение `112` означает контекст партии, а не позицию карточки `n из 112`. |
| **Planned Card Count** | Плановое число карточек конкретного комплекта. Сумма по комплектам может превышать `Batch Quantity`. |
| **Assignee / исполнитель** | Работник, которому мастер назначил карточку и для которого будет создана mock-запись нормо-часов. В MVP исполнитель не отправляет lifecycle-команды. |
| **Mass assignment / массовое назначение** | Команда мастера, назначающая выбранные карточки одного комплекта одному исполнителю атомарно. Последовательные команды могут сформировать распределение `60 + 52 = 112`. |

## Приёмка и жизненный цикл

| Термин | Каноническое определение |
|---|---|
| **First-article card** | Одна внутренняя карточка комплекта, выбранная мастером для прохождения gate. Её UUID не является номером первой физической детали. |
| **First-article gate** | Состояние `WorkCardSet`: `FIRST_ARTICLE_PENDING` до положительной приёмки и `SERIAL_ALLOWED` после неё. |
| **FirstPieceAcceptance / приёмка первой детали** | Отдельный факт `CONFIRMED_AS_IS`: БТК принимает первую деталь до серийного запуска. В MVP представлен positive-only командой `AcceptFirstArticle`. |
| **Master work recording** | Команды мастера, фиксирующие начало и завершение назначенной карточки. Они отражают ведение карточек мастером, а не self-service исполнителя. |
| **Operator self-control / самоконтроль** | Факт `CONFIRMED_AS_IS`: во время серии исполнитель контролирует свою работу. Отдельная цифровая команда self-check в MVP отсутствует. |
| **FinalBatchAcceptance / финальная приёмка партии** | Факт `CONFIRMED_AS_IS`: после завершения БТК принимает всю партию. В MVP это также одна неизменяемая цифровая запись `TO_BE_DECISION`, связанная с `ProductionBatch`; она не является состоянием отдельной `WorkCard` и не заменяет физические подписи. |
| **RecordFinalBatchAcceptance** | Positive-only команда `QUALITY_CONTROLLER` уровня партии. После всех обязательных first-article gates и `CLOSED` WorkCard создаёт одну `FinalBatchAcceptance` и `FinalBatchAccepted` в общей транзакции. |
| **WorkCardQualityConfirmation** | `TO_BE_DECISION`: positive-only `ConfirmWorkCardQuality` для одной завершённой serial-карточки; атомарно переводит её в `CLOSED`, но не записывает `FinalBatchAcceptance` и не заменяет физическую подпись БТК. |
| **Close / цифровое закрытие карточки** | Терминальное состояние отдельной WorkCard после `AcceptFirstArticle` или синтетического per-card `ConfirmWorkCardQuality`. `CLOSED` не доказывает финальную приёмку всей партии. |
| **Optimistic concurrency** | Проверка ожидаемой версии каждого изменяемого агрегата; конфликт не перезаписывается молча. |

## История и mock-интеграция

| Термин | Каноническое определение |
|---|---|
| **Business command** | Явное намерение изменить состояние, проверяемое по роли, данным, состоянию и версии. |
| **Domain event / audit event** | Неизменяемый факт успешной бизнес-команды. Каждая успешная изменяющая команда, включая создание партии, имеет событие. |
| **Audit log** | Упорядоченная история событий карточки, комплекта, партии или коррелированной операции; не является механизмом изменения состояния. |
| **Mock payroll export** | Идемпотентное создание демонстрационной записи нормы закрытой карточки; не рассчитывает зарплату или фактическое время. |
| **PayrollRecord** | Единственная неизменяемая запись `workCardId + beneficiaryId + normHoursSnapshot`. |

## Роли MVP

| Роль | Ответственность |
|---|---|
| **`PLANNER` / ПДБ** | Выбрать подготовленный паспорт, создать партию и один раз выпустить все комплекты. |
| **Технолог** | Источник паспорта и состава операций; не интерактивная роль MVP. |
| **БТБ** | Источник operation-scoped норм; не интерактивная роль MVP. |
| **`MASTER`** | Выбрать first-article карточку, назначать карточки и фиксировать начало/завершение. |
| **`WORKER`** | Read-only представление своей назначенной работы; assignee/beneficiary. Подтверждённый самоконтроль не имеет отдельной digital-команды MVP. |
| **`QUALITY_CONTROLLER`** | Выполнить digital first-piece gate, синтетическое per-card подтверждение и отдельную `RecordFinalBatchAcceptance` всей завершённой партии. |
| **`ADMIN_AUDITOR`** | Читать аудит и создавать/читать mock payroll-запись. |

## Языковые правила

- технический `WorkCardId` называется UUID/внутренним ID, а не номером карточки или детали;
- запрещены пользовательские формулировки `#01`, `3 из 12` и «диапазон 1..N»;
- `112 карточек в комплекте` не означает `112 идентифицированных деталей`;
- **первая деталь** — производственная контрольная точка, а не серийно идентифицированная сущность в модели;
- **экспорт** означает mock-фиксацию нормо-часов, а не деньги или выплату.
