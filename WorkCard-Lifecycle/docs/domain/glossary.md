# Glossary

Канонический словарь терминов MVP v1. Термины описывают синтетическую предметную область case study и не претендуют на совпадение с регламентами конкретного предприятия.

## Производственное планирование

| Термин | Каноническое определение |
|---|---|
| **Production Batch / производственная партия** | Синтетическое задание на выпуск заданного количества одинаковых экземпляров по выбранному маршруту и нормативу. Партия служит источником выпуска комплекта карточек. |
| **Quantity / количество экземпляров** | Положительное целое число экземпляров в партии. После выпуска оно должно совпадать с количеством созданных `WorkCard`. |
| **Route / маршрут** | Упорядоченное описание работы, необходимое для демонстрационного сценария. В MVP маршрут задаётся синтетическими данными и не интегрируется с MES или ERP. |
| **Norm Hours / нормо-часы** | Нормативная длительность работы, используемая только для демонстрационной записи начисления. Это не фактически отработанное время и не денежная сумма. |

## Карточки работы

| Термин | Каноническое определение |
|---|---|
| **Release / выпуск карточек** | Бизнес-действие, которое один раз создаёт для партии `WorkCardSet` и ровно по одной `WorkCard` на каждый экземпляр. |
| **WorkCardSet / комплект карточек** | Группа карточек, выпущенная для одной производственной партии. Комплект задаёт общую связь карточек с партией, но не заменяет их отдельный жизненный цикл. |
| **WorkCard / рабочая карточка** | Отдельная единица учёта работы над одним экземпляром. Карточка имеет собственные идентификатор, состояние, исполнителя, версию и историю. |
| **Assignee / исполнитель карточки** | Демонстрационный пользователь с ролью исполнителя, которому мастер назначил карточку. Назначение определяет, кто вправе начать и завершить работу по ней. |
| **Mass assignment / массовое назначение** | Одна бизнес-команда мастера, назначающая выбранные карточки одному исполнителю атомарно: либо назначены все допустимые карточки, либо ни одна. |

## Контроль жизненного цикла

| Термин | Каноническое определение |
|---|---|
| **Business command / бизнес-команда** | Явное намерение пользователя изменить предметное состояние. Команда проходит проверки роли, текущего состояния, входных данных и версии объекта. |
| **WorkCard status / состояние карточки** | Этап жизненного цикла `WorkCard`, изменяемый только допустимой бизнес-командой согласно [[work-card-state-machine]]. |
| **Master confirmation / подтверждение мастера** | Подтверждение мастером, что завершённая исполнителем работа может быть передана на контроль качества. |
| **БТК / контроль качества** | Контрольная роль, которая в MVP подтверждает качество после подтверждения мастером. Положительное подтверждение атомарно закрывает карточку; отклонение и цикл доработки относятся к итерации 2. |
| **Close / закрытие карточки** | Финализация карточки как результат положительного подтверждения БТК. Только закрытая карточка допускается к mock payroll export. |
| **Optimistic concurrency / контроль версии** | Проверка, что команда применяется к ожидаемой версии объекта. Конфликтующая запись отклоняется, а не перезаписывает более новое состояние молча. |

## История и mock-интеграция

| Термин | Каноническое определение |
|---|---|
| **Domain event / доменное событие** | Неизменяемый факт о состоявшемся бизнес-действии, названный в прошедшем времени. Событие возникает только после успешного выполнения команды. |
| **Audit event / событие аудита** | Запись значимого действия с типом события, временем, субъектом и ссылкой на объект. Изменение состояния и соответствующее событие сохраняются согласованно. |
| **Audit log / журнал аудита** | Упорядоченная история событий, позволяющая восстановить жизненный цикл карточки. Журнал не является механизмом изменения состояния. |
| **Mock payroll export / демонстрационный экспорт** | Идемпотентная передача данных закрытой карточки в имитацию payroll-системы. Экспорт не рассчитывает зарплату, налоги или выплаты. |
| **Payroll record / запись начисления** | Единственная демонстрационная запись нормо-часов для экспортированной карточки. Повторная команда не создаёт вторую запись. |

## Роли MVP

| Роль | Ответственность в предметной области |
|---|---|
| **Планировщик** | Создаёт синтетическую партию и выпускает комплект карточек. |
| **Мастер** | Массово назначает карточки и подтверждает завершённую работу. |
| **Исполнитель** | Начинает и завершает только назначенную ему карточку. |
| **Контролёр БТК** | Подтверждает качество карточки после подтверждения мастером. |
| **Администратор / аудитор** | Просматривает историю и запускает mock payroll export закрытой карточки. |

## Языковые правила

- `WorkCard` и `WorkCardSet` используются как имена доменных типов и не переводятся в коде.
- **Завершить работу**, **подтвердить мастером** и **подтвердить БТК** — разные бизнес-команды; успешное подтверждение БТК закрывает карточку в той же транзакции.
- **Выпуск** означает создание карточек, а не физический выпуск продукции.
- **Экспорт** означает фиксацию демонстрационной передачи, а не расчёт или выплату зарплаты.
