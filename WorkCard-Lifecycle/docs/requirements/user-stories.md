# User Stories

| ID | История | Use case | Acceptance criteria |

| US-001 | Как **ПДБ / PLANNER**, я хочу выбрать подготовленный паспорт и создать партию с количеством, не редактируя операции и нормы. | `UC-001` | `AC-BAT-001`, `AC-AUT-001`, `AC-AUD-001` |
| US-002 | Как **ПДБ / PLANNER**, я хочу одним выпуском создать все operation-scoped комплекты и карточки плана. | `UC-002` | `AC-BAT-002`, `AC-BAT-003`, `AC-TXN-001` |
| US-003 | Как **мастер**, я хочу атомарно назначать first-article и serial-карточки и видеть итоговое распределение объёма. | `UC-003` | `AC-ASG-001`–`AC-ASG-003` |
| US-004 | Как **мастер**, я хочу зафиксировать начало назначенной работы от имени процесса, сохранив фактического исполнителя. | `UC-004` | `AC-LIF-001`, `AC-AUT-002`, `AC-CON-001` |
| US-005 | Как **мастер**, я хочу зафиксировать завершение начатой работы, чтобы передать карточку БТК. | `UC-004` | `AC-LIF-002`, `AC-AUT-002`, `AC-CON-001` |

| US-015 | Как **пользователь команды**, я хочу перечитать все затронутые агрегаты после conflict и продолжить осознанно. | `UC-012` | `AC-CON-001`, `AC-CON-002` |
| US-016 | Как **администратор-аудитор**, я хочу прочитать существующую `PayrollRecord` без повторного export. | `UC-013` | `AC-READ-003`, `AC-PAY-005`, `AC-AUT-003` |

| US-021 | Как **контролёр БТК**, я хочу отдельным действием принять всю завершённую партию и прочитать неизменяемую запись, чтобы финальная приёмка не выводилась из закрытых карточек и не дублировалась. | `UC-015` | `AC-FBA-001`–`AC-FBA-007` |

## Границы историй

- `WORKER` — assignee/beneficiary и read-only demo-роль, не автор `StartWorkCard`/`CompleteWorkCard`;
- `US-006` моделирует первую приёмку, `US-007` — синтетическое per-card закрытие, а только `US-021` — отдельную финальную приёмку всей партии;
- `US-003` не включает переназначение и не использует номера деталей;
- `US-010`/`US-011` описывают нормо-часы, а не деньги, налоги или фактическое время;
- UI не даёт права обходить backend permissions, state machine или gate.

## Правило готовности

История готова к реализации, когда её use case, criteria и связанные [[negative-scenarios]] однозначны. Закрытие требует реализованных и прошедших тестов из [[requirements-traceability]].
