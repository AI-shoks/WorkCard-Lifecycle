# Negative Scenarios

Каталог обязательных отказов MVP v1. Во всех строках действует единый постконтракт: предметные данные и версии не изменены; доменное событие или audit event об успешном действии не создано; клиент получает явный безопасный отказ. Точные HTTP-коды и формат ошибки определит [[api-contracts]]; здесь фиксируется предметная категория.

| ID | Условие | Ожидаемый результат | Категория | Правила / критерии |
|---|---|---|---|---|
| NS-001 | Количество не положительное целое, нормо-часы не положительны либо обязательные данные партии отсутствуют. | Партия не создаётся. | validation | `BR-010`, `BR-011`; `AC-BAT-001` |
| NS-002 | Роль не имеет права на запрошенную команду. | Backend отклоняет команду независимо от UI. | authorization | `BR-001`; `AC-AUT-001` |
| NS-003 | Выпуск уже выпущенной партии. | Второй комплект и новые карточки не создаются. | business conflict | `BR-012`, `BR-016`; `AC-BAT-003` |
| NS-004 | `expectedVersion` отсутствует или не совпадает с текущей версией существующего изменяемого агрегата. | Команда отклоняется; клиент должен перечитать объект. | concurrency conflict | `BR-002`, `BR-061`; `AC-CON-001` |
| NS-005 | При выпуске не удаётся создать комплект, хотя бы одну карточку или событие. | Откатываются партия, комплект, все карточки и события операции. | transactional failure | `BR-013`, `BR-051`, `BR-062`; `AC-TXN-001` |
| NS-006 | Массовое назначение содержит пустой набор, повторяющиеся ID или невалидного исполнителя. | Ни одна карточка не назначается. | validation | `BR-020`; `AC-ASG-002` |
| NS-007 | Хотя бы одна выбранная карточка отсутствует, уже назначена или не в `RELEASED`. | Отклоняется весь набор без частичного назначения. | business conflict | `BR-021`, `BR-022`; `AC-ASG-002` |

| NS-009 | Попытка переназначить или снять назначение. | Команда недоступна или отклонена; `assigneeId` не меняется. | out of scope | `BR-024`; `AC-ASG-003` |
| NS-010 | Исполнитель начинает или завершает чужую карточку. | Команда отклоняется после серверной проверки `actorId = assigneeId`. | ownership | `BR-030`, `BR-031`; `AC-AUT-002` |
| NS-011 | `StartWorkCard` вызвана не для `ASSIGNED`. | Переход не выполняется. | state conflict | `BR-030`; `AC-LIF-001` |
| NS-012 | `CompleteWorkCard` вызвана не для `IN_PROGRESS`, включая завершение без начала. | Переход не выполняется. | state conflict | `BR-031`; `AC-LIF-002` |
| NS-013 | Исполнитель повторяет уже успешное начало или завершение. | Повторный переход не выполняется и новое событие не создаётся. | state conflict | `BR-003`, `BR-030`, `BR-031`; `AC-LIF-001`, `AC-LIF-002` |
| NS-014 | Мастер подтверждает карточку до `COMPLETED`. | Статус не меняется. | state conflict | `BR-032`; `AC-LIF-003` |
| NS-015 | Мастер повторно подтверждает уже `MASTER_CONFIRMED` или `CLOSED`. | Повторный переход и событие не создаются. | state conflict | `BR-032`, `BR-035`; `AC-LIF-003`, `AC-LIF-005` |
| NS-016 | БТК подтверждает карточку до `MASTER_CONFIRMED`. | Карточка не закрывается. | state conflict | `BR-033`; `AC-LIF-004` |

| NS-020 | Экспорт запрошен для карточки не в `CLOSED` или без исполнителя. | `PayrollRecord` и событие экспорта не создаются. | business conflict | `BR-040`; `AC-PAY-003` |
| NS-021 | Повторный export запрошен для уже экспортированной закрытой карточки. | Возвращается существующая запись; новая запись и событие отсутствуют. | idempotent replay | `BR-041`, `BR-043`; `AC-PAY-002` |
| NS-022 | Клиент пытается изменить ID, снимок маршрута/нормы, событие истории или закрытую карточку. | Изменение отклоняется или не предоставляется контрактом. | immutability | `BR-004`, `BR-015`, `BR-035`, `BR-042`, `BR-052`; `AC-AUD-002`, `AC-LIF-005` |

| NS-024 | Клиент подменяет роль или `assigneeId` в теле запроса. | Backend использует доверенную идентичность и повторно проверяет полномочия/владение. | tampering | `BR-001`; `AC-AUT-001`, `AC-AUT-002` |

| NS-034 | Событие не содержит обязательного типа, времени, агрегата, версии, субъекта, команды, корреляции или типизированных данных. | Транзакция не фиксирует неполную оболочку. | event schema | `BR-050`; `AC-AUD-001`, `AC-AUD-004` |
| NS-035 | Событие массовой операции имеет чужой `correlationId` или не связано с исходным `commandId`. | Непоследовательный набор не считается допустимым результатом и не фиксируется. | audit correlation | `BR-050`, `BR-051`; `AC-AUD-003`, `AC-AUD-004` |
| NS-036 | История возвращена не по версии и времени либо при равном времени нарушает порядок версий. | Система обязана вернуть детерминированно упорядоченную историю. | ordering | `BR-053`; `AC-AUD-001` |

## Порядок безопасной обработки

Backend устанавливает доверенную идентичность, проверяет полномочие роли, загружает доступные цели, затем проверяет владение, состояние, инварианты и версии. Ошибка не должна раскрывать чувствительные сведения о недоступном объекте. Различение `authorization`, `not found` и `conflict` на уровне HTTP принимается только в [[api-contracts]] и не может ослабить этот постконтракт.

## Вне негативного каталога MVP

Каталог не определяет поведение для отклонения БТК, доработки, переназначения, повторного выпуска, спора/версии нормы и реального payroll: эти функции отсутствуют, а не являются скрытыми альтернативными потоками.
