# Render Free deployment configuration

Этот каталог описывает текущий контракт [ADR-0009](../../docs/architecture/adr/0009-render-free-neon-free-release.md): один Free image-backed web service, public GHCR digest, health path `/health/live`, без previews, disks, Render jobs и постоянного staging service. Владелец разрешил первый deployment и необходимые scoped действия только для установленных ресурсов этого проекта. Платные планы, payment methods, add-ons/overage и GCP apply/destroy запрещены. Первый работающий публичный deployment ещё не подтверждён release record.

SPA и Fastify API запускаются одним nonroot image. Render не собирает исходники; release workflow собирает один `linux/amd64` image и публикует его в GHCR. После первого отдельного изменения package visibility anonymous pull обязателен; `resume_run_id` продолжает исходную публикацию того же digest без rebuild. Постоянный image reference и resolved deployment digest сверяются adapter; mutable tag и один HTTP 202 не являются доказательством успешно запущенного release. Previous image фиксируется в durable evidence до изменения сервиса; live record — до browser smoke.

Актуальный [Render OpenAPI](https://api-docs.render.com/openapi/render-public-api-1.json) различает конфигурацию и deployment: `PATCH /services/{id}` принимает `image: { ownerId, imagePath }`, а `GET /services/{id}` возвращает постоянный `imagePath`. `POST /services/{id}/deploys` принимает `imageUrl`; `201` содержит deploy, `202` может не содержать его ID. После rollout нужны `status=live`, совпадение `image.ref` с immutable reference и `image.sha` с digest manifest, затем повторное чтение persistent reference. Отсутствие registry credentials проверяется также по документированному верхнему `service.registryCredential`, а не только по входному `image.registryCredentialId`. При создании `serviceDetails.plan=free` задаётся явно: API default `0.5c-512mb` платный. Render требует `linux/amd64`, image не больше 10 GB в сжатом виде и доступность digest в registry при каждом новом pull; собственный image archive платформа не предоставляет. [Prebuilt images](https://render.com/docs/deploying-an-image)

Runtime получает только `DATABASE_URL`, `SESSION_SIGNING_SECRET` и несекретные имена target/origin/proxy из [environment matrix](../../docs/engineering/environments.md). Owner tasks того же digest выполняются одноразовым Docker на Actions/local с `MIGRATION_DATABASE_URL`; DB owner не помещается в Render runtime. Первый service стартует с `PROXY_TRUST_MODE=observe` без `PROXY_TRUSTED_CIDRS`: forwarded headers не доверяются, `/api*` и readiness принудительно `503` до DB, liveness/SPA/peer logs доступны. Initial owner migration также оставляет persistent gate закрытым. После наблюдения actual peers рассматриваются exact IP/CIDR и mode `render`; до открытия demo обязательны chain/client-IP/spoof qualification и bootstrap + verify. Произвольный all-network allowlist и угадывание диапазона запрещены; полный порядок — в [Deployment](../../docs/release/deployment.md#первый-запуск-без-предположения-о-proxy).

Render liveness не касается PostgreSQL. Readiness, migration history, maintenance/freshness и browser security проверяются отдельно при release. Никаких startup migrations и keepalive. На 2026-09-17 текущий Render Hobby включает общие для workspace 5 GB/month outbound bandwidth и 750 Free instance hours; каждый из двух Neon Free projects — собственные 100 CU-hours/month, 0.5 GB storage и 5 GB/month public transfer. PG18 в Neon доступен без preview-ограничений с 2026-05-01. Подробные limits, sleep/suspension и официальные источники — в [ADR](../../docs/architecture/adr/0009-render-free-neon-free-release.md). Проверка документации не подтверждает фактические аккаунты, их billing settings или остатки квот; это отдельный preflight первого запуска.

Все команды первого разрешённого запуска, secret boundaries, current/previous image retention, daily/manual reset и rollback находятся в [Deployment](../../docs/release/deployment.md). [GCP Terraform](../terraform/README.md) сохранён только как история.
